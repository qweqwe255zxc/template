# Шаблон лендинга «Модуль»

База, из которой разворачиваются клиентские сайты. Страница целиком описывается одним файлом `content/site.config.ts`: типы секций, варианты раскладок, поверхности, тексты и реквизиты. Компоненты при сборке нового проекта трогать не нужно — меняются конфиг и токены.

Демо-конфиг в репозитории — вымышленное агентство: он существует, чтобы сравнивать варианты секций, а не как продакшен-лендинг.

## Стек

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · lucide-react · imask.
Без UI-библиотек и без бэкенда: заявки уходят в Telegram и на почту через `/api/contact`.

## Запуск

```bash
npm install
cp .env.example .env.local   # можно оставить пустым — форма будет писать заявки в лог
npm run dev                  # http://localhost:3000
```

| Скрипт | Что делает |
|---|---|
| `npm run dev` | дев-сервер |
| `npm run build` | продакшен-сборка |
| `npm run start` | запуск собранного |
| `npm run typecheck` | `tsc --noEmit`, обязателен перед сдачей правки |
| `npm run new-project` | разворачивает копию шаблона под новый проект (`scripts/new-project.mjs`) |

## Новый проект — порядок действий

Полный алгоритм со всеми обязательными шагами — `CLAUDE.md` §5. Коротко:

1. Палитра и шрифты из брифа клиента — **в двух файлах**: `theme/tokens.css` (CSS-переменные) и `theme/palette.ts` (рантайм-дубль для favicon, OG-картинки и `themeColor`). Оставлять демо-цвета (`--palette-accent: #8c2434`) нельзя.
2. Шрифт подключается в `app/layout.tsx` через `next/font/google`; в `subsets` обязателен `"cyrillic"`.
3. Тариф оформления — `theme.preset`: `econom` (плоско, линейки) или `standard` (карточки, тени, скругления). Что именно меняется — `docs/presets.md`.
4. Варианты секций проставляются явно в `sections[].variant` (каталог — `CLAUDE.md` §2, подробности — `docs/section-system.md`). Пустой `variant` = дефолт пресета у всех секций сразу.
5. Поверхности секций чередуются по схеме `CLAUDE.md` §3: один тёмный блок (`ink`), один акцентный (`accent`), остальные `paper`/`surface`.
6. **Перед сдачей удалить каталог `app/qa-audit/`** — это внутренний стенд, см. ниже.

## Что где лежит

```
app/               роуты: страница, /privacy, 404, robots, sitemap, OG-картинка, /api/*
components/ui/     примитивы: Button, Card, Container, Section, Accordion, Input, …
components/sections/<Тип>/
  index.tsx        роутер вариантов + dev-warn при неверном конфиге
  variants/        сами раскладки — 84 варианта в 12 типах секций
  parts/           куски, общие для нескольких вариантов
content/           site.config.ts — единственный файл, который правят под проект
theme/             tokens.css (все цвета, размеры, тени) + palette.ts (их дубль для рантайма)
types/site.ts      типы конфига: что можно задать секции и какие варианты существуют
lib/               иконки, маска телефона, SEO, пресет, вспомогательные раскладки
docs/              section-system.md (секции и варианты), presets.md (тарифы оформления)
```

## Переменные окружения

Все — необязательные, список и комментарии в `.env.example`. Без них форма продолжает работать: заявка печатается в лог сервера, а не теряется.

- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — заявки в телеграм;
- `RESEND_API_KEY`, `MAIL_FROM`, `MAIL_TO`, `MAIL_REPLY_TO` — заявки на почту.

Подписка из футера (`/api/subscribe`) — заглушка: печатает адрес в лог и возвращает пользователя обратно с подтверждением. Куда её девать по-настоящему, решает конкретный проект. Если подписка не нужна — уберите ключ `footer.newsletter` из конфига, и блок исчезнет из всех вариантов футера.

## Стенд вариантов `/qa-audit`

`/qa-audit/<секция>` рендерит **все** варианты секции подряд с подписями — на нём удобно выбирать раскладку и проверять адаптив на 390 / 768 / 1024 / 1440 / 1920. Стенд закрыт от индексации (`noindex` + `disallow` в `app/robots.ts`), но в клиентском проекте ему делать нечего: **перед сдачей удалить каталог `app/qa-audit/` целиком.**

Проверка проекта перед сдачей — навык `.claude/skills/release-audit`.
